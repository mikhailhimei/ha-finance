# Финансы для Home Assistant

Локальная интеграция с React-панелью «Финансы». Реализован учёт вкладов; зарплата рассчитывается по производственному календарю РФ; распределение бюджета позволяет планировать траты по выплатам.

## Установка через HACS

Добавьте `https://github.com/mikhailhimei/ha-finance` как пользовательский репозиторий категории «Интеграция». Установите версию `v0.1.1` или новее (либо актуальную `main`), перезапустите HA и добавьте «Финансы» через «Настройки → Устройства и службы → Добавить интеграцию». Сборка React уже включена в репозиторий, Node.js на сервере HA не требуется.

Если HACS показывает старый коммит `67968f9`, обновите сведения о репозитории и выберите новую версию в меню повторной загрузки.

## Ручная установка и сборка

Требуется Home Assistant Core 2025.1+ и Node.js 22+ для сборки интерфейса.

```sh
npm ci --cache /workspace/.npm-cache
npm run build
```

Скопируйте **всю** папку `custom_components/ha_finance`, включая собранную `frontend`, в `config/custom_components/ha_finance` вашей установки HA. Перезапустите HA и добавьте интеграцию «Финансы» через «Настройки → Устройства и службы → Добавить интеграцию». В боковом меню появится «Финансы».

Готовая сборка frontend хранится в Git для установки через HACS. После изменения React-кода выполните `npm run build` и включите обновлённые файлы `custom_components/ha_finance/frontend` в коммит.

## Как считаются деньги

- Общая сумма — начальное тело вклада плюс полученные доходы; это не банковский процентный вклад, проценты автоматически не начисляются.
- Текущий остаток = общая сумма − оплаченные расходы.
- Ожидаемые расходы = расходы без галочки.
- Свободно после планов = остаток − ожидаемые расходы; допускается отрицательная сумма с предупреждением.
- Расход вводится положительным числом, например `47000`; интерфейс показывает его со знаком минус.
- Галочка изменяет статус расхода. Повторная установка не списывает деньги дважды, снятие восстанавливает остаток.
- Изменение начальной суммы не удаляет операции. Кнопка «Добавить» позволяет выбрать расход или доход. Неотмеченный доход не увеличивает общую сумму и доступные деньги. У полученной/оплаченной операции появляется крестик с подтверждением удаления в нижней шторке; удаление отменяет её влияние на суммы. Старые записи без типа считаются расходами.
- Суммы хранятся целыми копейками, валюта — рубли.

## Общий доступ и хранение

Данные сохраняются через HA Store в `.storage/ha_finance` и входят в резервную копию конфигурации HA. Все аутентифицированные пользователи HA имеют одинаковый доступ к просмотру и изменению. Анонимный доступ отсутствует. Изменения передаются открытым панелям через WebSocket. Запись сериализована; при одновременном редактировании одного поля сохраняется последнее изменение.

## Напоминания для автоматизаций

Интеграция раз в минуту проверяет даты по часовому поясу HA. Для неоплаченного расхода с наступившей датой генерируется событие `ha_finance_expense_due` — один раз для его текущей даты. При запуске также проверяются просроченные расходы, чтобы обработать время простоя. Изменение даты позволяет новому напоминанию сработать. Оплата и снятие галочки не сбрасывают уже отправленное напоминание.

Пример автоматизации (замените `notify.notify` своим сервисом):

```yaml
alias: Напоминание о платеже
triggers:
  - trigger: event
    event_type: ha_finance_expense_due
actions:
  - action: notify.notify
    data:
      title: "Пора оплатить: {{ trigger.event.data.expense_name }}"
      message: >-
        {{ trigger.event.data.deposit_name }}:
        {{ trigger.event.data.amount }} ₽,
        дата {{ trigger.event.data.due_date }}
```

Событие содержит `deposit_id`, `deposit_name`, `expense_id`, `expense_name`, `amount` (рубли), `currency`, `due_date`. Для выбора вклада задайте `event_data: {deposit_id: "..."}` в триггере. События HA не являются очередью доставки: автоматизация должна быть включена в момент события. При аварийном завершении между сохранением маркера и отправкой события напоминание может быть потеряно.

## Разработка

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
npm run build
npm test
```

Vite открывает только предпросмотр интерфейса; он не сохраняет данные. Рабочее подключение передаёт сама панель HA. Компоненты `Field`, `Metric`, `Modal` и модель расчётов отделены от отображения вкладов и пригодны для следующих разделов.

Тесты проверяют расчёты, оплату/отмену, пополнение, редактирование тела, удаление расходов, сроки и повторные напоминания. Проверка установки и WebSocket API на работающем HA выполняется отдельно: добавьте два пользователя, откройте панель у обоих, создайте вклад на 100000 ₽ и расход 47000 ₽, отметьте оплату и проверьте остаток 53000 ₽ у обоих; снимите галочку, перезапустите HA и проверьте сохранность данных. В «Инструменты разработчика → События» прослушайте `ha_finance_expense_due` и создайте неоплаченный расход на сегодня.

## Навигация панели

Левая кнопка в шапке открывает боковое меню Home Assistant. Правая кнопка открывает выбор финансовых разделов: нижнюю шторку на телефоне и меню на компьютере. Стили включены в компонент панели и работают внутри Shadow DOM HA.

Проверка панели в Chromium: установите Python Playwright, соберите frontend, запустите `python -m http.server 8765 --bind 127.0.0.1 --directory custom_components/ha_finance/frontend` и выполните `python tests/browser_panel.py`.

## Заработная плата

«Указать работника» открывает нижнюю шторку: наименование, тип дохода («Зарплата офф» или «Фиксированный доход»), месячный доход и два дня выплат. Данные общие для пользователей HA. Карточка открывает расчёт для выбранного месяца; карандаш позволяет изменить работника.

Выбирается **месяц выплат**. «Зарплата» выплачивается в указанное число выбранного месяца за вторую половину предыдущего месяца. «Аванс» — в указанное число выбранного месяца за 1–15 текущего месяца. Для каждого периода используется календарь именно месяца работы: аванс = доход / рабочие дни × рабочие дни 1–15; зарплата = доход − аванс предыдущего месяца. Копейки округляются один раз, две выплаты за один месяц работы точно равны доходу; выплаты в одном календарном месяце могут отличаться от него. Числа 29–31 ограничиваются концом месяца, нерабочие даты переносятся на предыдущий рабочий день.

При обновлении с v0.2.0 прежнее первое поле «Число оклада» становится «Число зарплаты», второе «Число зарплаты» становится «Число аванса»; сохранённые числа автоматически переносятся один раз.

Расчёт предполагает полностью отработанный месяц, федеральную пятидневку РФ. НДФЛ автоматически не удерживается: вводите доход на нужной вам основе. Региональные праздники, личный график, отпуска, больничные и премии пока не учитываются.

Федеральный календарь включён в `workdays.json`, интернет при расчёте не нужен. Источник: [python-holidays 0.108 / Russia](https://github.com/vacanza/holidays/blob/v0.108/holidays/countries/russia.py), включая переносы выходных и рабочие субботы. Для обновления данных: установите `holidays==0.108` в отдельное окружение и запустите `python scripts/generate_calendar.py`. Заготовлены 2024–2100 годы; выбор месяца выплат доступен с января 2025 по декабрь 2100. После 2027 календарь предварительный: будущие правительственные переносы выходных ещё не учтены, интерфейс показывает предупреждение. По мере утверждения переносов календарь необходимо обновлять.

Фиксированный доход повторяется каждый месяц: укажите сумму и число месяца. Сумма не делится по рабочим дням. Дата, попавшая на выходной/федеральный праздник, переносится на предыдущий рабочий день; 29–31 ограничиваются концом короткого месяца. В превью и на странице показываются одна сумма и дата.

## Распределение бюджета

При создании бюджета выберите месяц и год: они станут названием карточки, например «Ноябрь 2026». Месяц закреплён за бюджетом, внутри повторного выбора нет. «Посмотреть общий» расположен первым; ниже — выплаты всех работников и фиксированных доходов с учётом переноса нерабочих дат. Сумма на карточке выплаты показывает оставшиеся деньги после планов. Выбор выплаты показывает её диаграмму, общий доход, расходы по плану и свободные деньги; общий режим объединяет все выплаты месяца.

«Добавить трату» открывает нижнюю шторку с названием, суммой и комментарием. В общем режиме при нескольких датах выбирается дата дохода с общей суммой. Внутри даты привязка автоматическая, выбирать человека не требуется. Траты можно редактировать и удалять через карандаш. Все траты общие для пользователей HA, сохраняются по бюджету, месяцу и источнику выплаты. Зарплатные настройки и исходные суммы доходов не изменяются; уменьшается остаток для планирования. Разные бюджеты являются отдельными планами и могут использовать одни источники дохода. При удалении источника дохода его траты сохраняются в общем режиме, чтобы они не исчезали из итогов.

При обновлении старые бюджеты автоматически преобразуются в месячные карточки. Если в одном бюджете были траты за несколько месяцев, они разделятся по соответствующим месяцам без потери записей. Пустой старый бюджет получает текущий месяц HA.

В распределении бюджета выплаты с одинаковой фактической датой объединяются в одну карточку с совместным остатком. Нажатие открывает отдельный экран с диаграммой, доходами и тратами этой даты; «Посмотреть общий» открывает отдельный общий экран. Кнопка «Назад», системный возврат и свайп возвращают к списку дат, затем к месячным бюджетам. При добавлении траты внутри даты человек не выбирается: используется общий доход даты. В общем режиме даты сгруппированы и выбираются без списка работников.

Общий экран бюджета визуально разделяет траты на блоки по датам выплат, с отдельными доходами, расходами и остатками. Действие «Клонировать» у месячного бюджета позволяет выбрать другой месяц и копирует все траты, суммы, источники и комментарии с новыми идентификаторами; оригинал сохраняется. Доходы для нового месяца рассчитываются заново. На компьютере действия карточек открываются карандашом в диалоге, на сенсорном экране — долгим нажатием в нижней шторке.

## Долги

Создайте долг с названием и первоначальной суммой. Начальный остаток равен этой сумме. Внутри обе суммы расположены вертикально, ниже — история внесённых платежей. Долгое нажатие на карточку (карандаш на компьютере) открывает редактирование и удаление. Удаление внесённого платежа возвращает сумму в остаток. При изменении первоначальной суммы уже внесённые платежи сохраняются. «Добавить» открывает форму с единственным полем внесённой суммы; платёж уменьшает остаток, первоначальная сумма сохраняется. Нулевые платежи и платежи сверх остатка не допускаются. Данные хранятся в HA и обновляются у всех пользователей. На телефоне формы открываются нижней шторкой, на компьютере — модальным окном.

Новые и клонированные месячные бюджеты показываются первыми в списке.

## Настройки календаря и JSON

В меню «Настройки» выберите год (2024–2100). Текущий календарь можно скачать кнопкой «Скачать JSON» и использовать как шаблон. После изменения загрузите файл или вставьте JSON в редактор и нажмите «Применить календарь». Импорт сохраняется в HA, входит в резервные копии и немедленно применяется к расчётам зарплаты и бюджета у всех пользователей. Перезапуск после каждого импорта не требуется. «Восстановить встроенный» удаляет переопределение выбранного года.

Формат:

- `year`: целое число года.
- `confirmed`: `true`, если вы проверили данные по утверждённому календарю; иначе `false` (интерфейс сохраняет пометку предварительного расчёта).
- `days_off`: массив дат `YYYY-MM-DD` — полный список праздников и дополнительных выходных этого года. Обычные субботы и воскресенья можно не перечислять; скачанный шаблон содержит их для удобства. Все федеральные праздники, включая 1–8 января, должны присутствовать.
- `working_days`: массив дат `YYYY-MM-DD` — рабочие субботы и воскресенья. Дату нельзя одновременно указать в обоих массивах. Для переноса с рабочей субботы на понедельник укажите субботу в `working_days`, понедельник — в `days_off`.

[Полный пример за 2026 год](examples/calendar-2026.json). Импорт полностью заменяет правила выбранного года, поэтому лучше редактировать скачанный шаблон. Неверный год, противоречащие или повторяющиеся даты, пропущенные федеральные праздники и месяц без рабочих дней отклоняются без изменения сохранённых данных. Доходы и запланированные суммы трат не изменяются; пересчитываются даты, зарплатные суммы и свободные деньги бюджета. Утверждённые будущие переносы можно добавить этим способом без новой версии интеграции. Кнопка «Получить автоматически» запрашивает год из isDayOff (`https://isdayoff.ru/api/getdata?year=ГОД&cc=ru`), проверяет полноту ответа и федеральные праздники и помещает JSON в редактор. Сохранение — отдельной кнопкой «Применить календарь». Для получения HA нужен HTTPS-доступ к isdayoff.ru. Будущие годы могут быть ещё не опубликованы; при ошибке текущий календарь не изменяется. Полученный календарь имеет `confirmed: false`: перед изменением на `true` проверьте его по утверждённым переносам. Ручной импорт работает без внешнего сервиса.

## Подтипы трат бюджета

Название траты открывает отдельный экран категории. Например, «Здоровье» с суммой 21 000 ₽ можно распределить на «Кровь», «Моча» и другие подтипы: у каждого название, сумма и необязательный комментарий. Сверху показана исходная сумма категории, ниже — распределено и осталось распределить. «Добавить» открывает форму подтипа (нижняя шторка на телефоне, модальное окно на компьютере). Через карандаш подтип можно изменить или удалить. Кнопка «Назад», системный возврат и свайп возвращают к тратам.

Подтипы детализируют уже зарезервированную сумму категории и не списываются из общего бюджета повторно. При превышении суммы категории показывается предупреждение. Изменение суммы родительской категории сохраняет подтипы; клонирование месячного бюджета копирует их независимо, с новыми идентификаторами. Данные общие для пользователей и сохраняются в HA вместе с бюджетом.
