# Финансы для Home Assistant

Локальная интеграция с React-панелью «Финансы». Реализован учёт вкладов; зарплата рассчитывается по производственному календарю РФ; распределение бюджета пока представлено вкладкой-заглушкой.

## Установка через HACS

Добавьте `https://github.com/mikhailhimei/ha-finance` как пользовательский репозиторий категории «Интеграция». Установите версию `v0.1.1` или новее (либо актуальную `main`), перезапустите HA и добавьте «Финансы» через «Настройки → Устройства и службы → Добавить интеграцию». Сборка React уже включена в репозиторий, Node.js на сервере HA не требуется.

Если HACS показывает старый коммит `67968f9`, обновите сведения о репозитории и выберите новую версию в меню повторной загрузки.

## Ручная установка и сборка

Требуется Home Assistant Core 2025.1+ и Node.js 22+ для сборки интерфейса.

```sh
npm ci --cache /workspace/.npm-cache
npm run build
```

Скопируйте **всю** папку `custom_components/ha_finance`, включая собранную `frontend`, в `config/custom_components/ha_finance` вашей установки HA. Перезапустите HA и добавьте интеграцию «Финансы» через «Настройки → Устройства и службы → Добавить интеграцию». В боковом меню появится «Финансы».

Готовая сборка frontend хранится в Git для установки через HACS. После изменения React-кода выполните `npm run build` и включите обновлённые файлы `custom_components/ha_finance/frontend` в коммит.

## Как считаются деньги

- Общая сумма — начальное тело вклада плюс полученные доходы; это не банковский процентный вклад, проценты автоматически не начисляются.
- Текущий остаток = общая сумма − оплаченные расходы.
- Ожидаемые расходы = расходы без галочки.
- Свободно после планов = остаток − ожидаемые расходы; допускается отрицательная сумма с предупреждением.
- Расход вводится положительным числом, например `47000`; интерфейс показывает его со знаком минус.
- Галочка изменяет статус расхода. Повторная установка не списывает деньги дважды, снятие восстанавливает остаток.
- Изменение начальной суммы не удаляет операции. Кнопка «Добавить» позволяет выбрать расход или доход. Неотмеченный доход не увеличивает общую сумму и доступные деньги. У полученной/оплаченной операции появляется крестик с подтверждением удаления в нижней шторке; удаление отменяет её влияние на суммы. Старые записи без типа считаются расходами.
- Суммы хранятся целыми копейками, валюта — рубли.

## Общий доступ и хранение

Данные сохраняются через HA Store в `.storage/ha_finance` и входят в резервную копию конфигурации HA. Все аутентифицированные пользователи HA имеют одинаковый доступ к просмотру и изменению. Анонимный доступ отсутствует. Изменения передаются открытым панелям через WebSocket. Запись сериализована; при одновременном редактировании одного поля сохраняется последнее изменение.

## Напоминания для автоматизаций

Интеграция раз в минуту проверяет даты по часовому поясу HA. Для неоплаченного расхода с наступившей датой генерируется событие `ha_finance_expense_due` — один раз для его текущей даты. При запуске также проверяются просроченные расходы, чтобы обработать время простоя. Изменение даты позволяет новому напоминанию сработать. Оплата и снятие галочки не сбрасывают уже отправленное напоминание.

Пример автоматизации (замените `notify.notify` своим сервисом):

```yaml
alias: Напоминание о платеже
triggers:
  - trigger: event
    event_type: ha_finance_expense_due
actions:
  - action: notify.notify
    data:
      title: "Пора оплатить: {{ trigger.event.data.expense_name }}"
      message: >-
        {{ trigger.event.data.deposit_name }}:
        {{ trigger.event.data.amount }} ₽,
        дата {{ trigger.event.data.due_date }}
```

Событие содержит `deposit_id`, `deposit_name`, `expense_id`, `expense_name`, `amount` (рубли), `currency`, `due_date`. Для выбора вклада задайте `event_data: {deposit_id: "..."}` в триггере. События HA не являются очередью доставки: автоматизация должна быть включена в момент события. При аварийном завершении между сохранением маркера и отправкой события напоминание может быть потеряно.

## Разработка

```sh
npm ci --cache /workspace/.npm-cache
npm run dev
npm run build
npm test
```

Vite открывает только предпросмотр интерфейса; он не сохраняет данные. Рабочее подключение передаёт сама панель HA. Компоненты `Field`, `Metric`, `Modal` и модель расчётов отделены от отображения вкладов и пригодны для следующих разделов.

Тесты проверяют расчёты, оплату/отмену, пополнение, редактирование тела, удаление расходов, сроки и повторные напоминания. Проверка установки и WebSocket API на работающем HA выполняется отдельно: добавьте два пользователя, откройте панель у обоих, создайте вклад на 100000 ₽ и расход 47000 ₽, отметьте оплату и проверьте остаток 53000 ₽ у обоих; снимите галочку, перезапустите HA и проверьте сохранность данных. В «Инструменты разработчика → События» прослушайте `ha_finance_expense_due` и создайте неоплаченный расход на сегодня.

## Навигация панели

Левая кнопка в шапке открывает боковое меню Home Assistant. Правая кнопка открывает выбор финансовых разделов: нижнюю шторку на телефоне и меню на компьютере. Стили включены в компонент панели и работают внутри Shadow DOM HA.

Проверка панели в Chromium: установите Python Playwright, соберите frontend, запустите `python -m http.server 8765 --bind 127.0.0.1 --directory custom_components/ha_finance/frontend` и выполните `python tests/browser_panel.py`.

## Заработная плата

«Указать работника» открывает нижнюю шторку: наименование, тип дохода («Зарплата офф» или «Фиксированный доход»), месячный доход и два дня выплат. Данные общие для пользователей HA. Карточка открывает расчёт для выбранного месяца; карандаш позволяет изменить работника.

Выбирается **месяц выплат**. «Зарплата» выплачивается в указанное число выбранного месяца за вторую половину предыдущего месяца. «Аванс» — в указанное число выбранного месяца за 1–15 текущего месяца. Для каждого периода используется календарь именно месяца работы: аванс = доход / рабочие дни × рабочие дни 1–15; зарплата = доход − аванс предыдущего месяца. Копейки округляются один раз, две выплаты за один месяц работы точно равны доходу; выплаты в одном календарном месяце могут отличаться от него. Числа 29–31 ограничиваются концом месяца, нерабочие даты переносятся на предыдущий рабочий день.

При обновлении с v0.2.0 прежнее первое поле «Число оклада» становится «Число зарплаты», второе «Число зарплаты» становится «Число аванса»; сохранённые числа автоматически переносятся один раз.

Расчёт предполагает полностью отработанный месяц, федеральную пятидневку РФ. НДФЛ автоматически не удерживается: вводите доход на нужной вам основе. Региональные праздники, личный график, отпуска, больничные и премии пока не учитываются.

Федеральный календарь включён в `workdays.json`, интернет при расчёте не нужен. Источник: [python-holidays 0.108 / Russia](https://github.com/vacanza/holidays/blob/v0.108/holidays/countries/russia.py), включая переносы выходных и рабочие субботы. Для обновления данных: установите `holidays==0.108` в отдельное окружение и запустите `python scripts/generate_calendar.py`. Заготовлены 2024–2027 годы; выбор месяца работы доступен с января 2025 по декабрь 2027. Неподдерживаемые даты возвращают ошибку, а не приблизительный расчёт по будням.

Фиксированный доход повторяется каждый месяц: укажите сумму и число месяца. Сумма не делится по рабочим дням. Дата, попавшая на выходной/федеральный праздник, переносится на предыдущий рабочий день; 29–31 ограничиваются концом короткого месяца. В превью и на странице показываются одна сумма и дата.
